## Queue

### 0. What to do with VMs 111/112 (b3pve1/b3pve2) — NEW, owner's call

They are no longer needed as cluster members. **b3pve1 is also the fork's
build machine**: build deps, `proxmox-biome`, and the non-root build user
that [`docs/upstream-sync.md`](../docs/upstream-sync.md) step 6 relies on.
Deleting both means the next upstream sync needs a new build VM first. Keeping
b3pve1 stopped and starting it only to build costs nothing but disk.

### 0a. Router source NAT to spx1 — optional now

It no longer affects the cluster. It still makes every service on spx1 see
VLAN 1001 clients as the public address. The fix is described in
[`docs/cluster.md`](../docs/cluster.md), *History*.

### 0b. Third physical host or QDevice — NEW

With two physical hosts, "b3p1 down + spx1 reboots" still needs a manual
`pvecm expected 3`. The next physical host (at 3 votes) closes that. Follow
[`docs/new-node.md`](../docs/new-node.md), plus
[`docs/join-existing-host.md`](../docs/join-existing-host.md) if it already
runs guests.

### 1. Apply the hardening runbook — BLOCKS PRODUCTION

What is still to rehearse, in order: WireGuard, internal DNS, ACME DNS-01
(needs the Cloudflare token), TOTP, step 7 + `verify.sh`, and the fail2ban
regex. Rerun `preflight.sh` first, because `ALLOW_FROM` now needs
b3p1 and spx1 too.

What the new pieces change:

- **Step 4 (TOTP):** the colleague account has no TOTP yet. Enforcing TOTP on
  the `pve` realm now affects a real user, so hand them the enrollment first.
- **Step 6 (firewall):** rules still only need 8006. The web redirect happens
  before the filter hooks.
- **Step 7 + `verify.sh`:** the "unreachable from the internet" test now has
  to cover 80 and 443 as well. `verify.sh` says so.
- **Step 3 (ACME):** DNS-01 is unaffected. `http-01` standalone would no
  longer work, because port 80 now goes to pveproxy.

### 2. Reboot test of the web redirect — NEW, small

The unit is enabled on every node, but none has rebooted since. The next
planned reboot should confirm that `http://<ip>/` still redirects.

### 3. Settle the domain of the UI links — BLOCKS RELEASE

`www/manager6/Utils.js:36-38` still points at `blue3.com.br`. These are
unconfirmed placeholders.

### 4. Internal DNS name for the UI — NEW, optional

Nothing resolves `b3pve1.blue3.cloud` or `pve.blue3.cloud` from the
workstation today. A name, together with the Let's Encrypt certificate from
runbook steps 2 and 3, removes the browser's certificate warning. With the
redirect, the address becomes `https://pve.blue3.cloud/`, with no port.
