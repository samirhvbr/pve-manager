## Queue

### 0. Router NAT to spx1 — BLOCKS THE .254 ENTRY POINT — NEW

The gateway source-NATs traffic addressed to spx1 to its public address, so
spx1 ↔ b3pve1/b3pve2 corosync links never come up. The fix is on the router:
exempt internal ↔ internal traffic from srcnat and clear the conntrack
entries for UDP 5405. Then start corosync on b3pve1/b3pve2 and check
`corosync-cfgtool -s` on every node. Exact steps: [`docs/cluster.md`](../docs/cluster.md),
*Known issue*.

### 0b. Third physical host or QDevice — NEW

With two physical hosts, "b3p1 down + spx1 reboots" still needs a manual
`pvecm expected 3`. The next physical host (at 3 votes) closes that. Follow
[`docs/new-node.md`](../docs/new-node.md), plus
[`docs/join-existing-host.md`](../docs/join-existing-host.md) if it already
runs guests.

### 1. Apply the hardening runbook — BLOCKS PRODUCTION

What is still to rehearse, in order: WireGuard, internal DNS, ACME DNS-01
(needs the Cloudflare token), TOTP, step 7 + `verify.sh`, and the fail2ban
regex. Rerun `preflight.sh` first, because `ALLOW_FROM` now needs
b3p1 and spx1 too.

What the new pieces change:

- **Step 4 (TOTP):** the colleague account has no TOTP yet. Enforcing TOTP on
  the `pve` realm now affects a real user, so hand them the enrollment first.
- **Step 6 (firewall):** rules still only need 8006. The web redirect happens
  before the filter hooks.
- **Step 7 + `verify.sh`:** the "unreachable from the internet" test now has
  to cover 80 and 443 as well. `verify.sh` says so.
- **Step 3 (ACME):** DNS-01 is unaffected. `http-01` standalone would no
  longer work, because port 80 now goes to pveproxy.

### 2. Reboot test of the web redirect — NEW, small
